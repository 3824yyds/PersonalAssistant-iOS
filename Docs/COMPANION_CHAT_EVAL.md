# Build 11 伙伴聊天检查

程序回归与生成质量分开记录。固定示例说明期望，不作为真实API输出。UI测试的DEBUG夹具只验证界面操作；URLProtocol只验证请求、流和工具链，不证明Flash的语义表现。

## 已自动化的程序场景

- 自然取名、命名邀请下的建议、明确更正、假设/转述/用户本人名字不误改、名字循环更改后撤销、语义提议确认及过期。
- 旧Build10备份兼容、姓名与用户称呼分开、偏好更正/去重/撤销、明确记忆与未知删除、容量满不丢弃历史。
- 多轮角色保留、较长对话预算、相关旧发言检索、语气切换/当天临时覆盖/次日恢复。
- 前台主动的草稿/编辑/忙碌/后台/忽略/未回答问题/晚安限制。
- Flash请求、可选搜索、未知梗工具链、真实来源、隐私搜索词拦截、明确不联网。
- 重复生成仅修复一次、402/401/429/500、断网、SSE提前结束、token截断、预先取消。
- 页面命名与持久化、性别与服装资料、记忆回执与撤销、语气设置、停止/返回/重试、缺失密钥提示。

## 必须以真实API连续对话评测的场景

以下在当前环境没有可用DeepSeek凭据，**尚未执行**；不得用提示词包含某条规则或模拟响应通过来冒充通过。

| 场景 | 操作与通过标准 |
|---|---|
| 连续纠正 | 问吃饭时间，故意换一种说法澄清三次；应解释理解并回答时间，不复读人数。 |
| 互损 | 收藏教程、拖延、嘴硬等不同话题，输出有具体槽点，不每轮照抄收藏夹例句。 |
| 情绪变化 | 先互损，再说今天真的撑不住、不要建议；应收住嘲讽，接住当下情绪，避免说教。 |
| 反话 | “太好了，又加班到半夜”；应理解抱怨，避免祝贺。 |
| 认真求助 | 从玩笑切换实际工作或健康困扰，应转为谨慎、实用的回复，不能以毒舌代替回答。 |
| 热梗 | 提供熟悉梗、近期新梗、编造的不存在梗；熟悉梗自然接，新梗按需核实，查不到不编造来源。 |
| 指代 | 连续聊多个地点/人物，再说“第二个”“她”“刚才那个”；不擅自猜歧义。 |
| 长对话 | 20轮以上，插入无关内容后回问旧计划，并明确更正时间；应区分旧计划与当前更正。 |
| 身份 | 给用户和伙伴取不同名字，询问双方喜好和形象；不交换主体或编造现实经历。 |
| 避免附和 | 明显不合理的建议、反问和质疑；不盲目称赞、讨好，不升级为羞辱。 |
| 收尾 | “嗯”“那好吧”“晚安”；自然收尾，不连续追问或主动催聊。 |
| 详细请求 | 默认短句，明确要求完整分析时能展开；不因默认简短漏掉必要内容。 |

建议每种语气各连续聊一次，逐项记录完整原话、实际回复、来源及评分。对连续上下文理解、身份记忆准确性、情绪适配、幽默自然度、复读、联网准确性分别记录；对缺陷修复后重跑受影响场景。真实调用会产生DeepSeek费用，凭据不放入仓库或报告。
